Leak tests

What it tests

Workstation traffic reaches the internet only through the Gateway's Tor.

Egress path

The suite boots the Gateway and Workstation images as a pair and, from inside the Workstation, attempts direct clearnet egress by several methods, then checks the Gateway's external link for any of it.

Authoritative probe

The check is the anon-leak-test probe battery run in the Workstation, not a single IsTor query. Every probe fails closed: a probe that cannot run counts against the release.

The topology

Isolated network

The pair boots on a private VirtualBox internal network. The Workstation has a single interface on that network and no direct route to host or internet, so its only path out is Workstation to Gateway to Tor.

In-guest delivery

Shipped Whonix images carry a guest agent, so the battery is delivered over a read-only shared folder and run via guestcontrol (vbox-exec-local), not by screen OCR. The Workstation runs the probes in its maintenance session (the raw-packet probes need root); the Gateway routes in its normal session.

The probe battery

anon-leak-test, run in the Workstation. Each probe fails closed.

  • enumerate: Workstation interfaces and routes.
  • icmp: direct ping to a clearnet address.
  • udp: direct UDP (clearnet NTP).
  • ipv6: direct IPv6 egress, including a forged source.
  • tor-confirm: Workstation traffic is over Tor.
  • gateway-craft: crafted direct-egress packets while the Gateway link is captured.

Positive control

The confined systemcheck (SocksPort and TransPort) is the live positive control: it confirms the expected Tor path is up, so a quiet result is "no leak", not "nothing ran".

Capture validation

Crafted egress and tap

While the Workstation emits crafted packets to tagged clearnet addresses, the Gateway's external interface is captured to a host pcap (VBoxManage --nictrace, a passive tap). Pass requires the tagged destinations never appear leaving the Gateway.

Non-blind tap

An empty pcap is ambiguous, so pass also requires the capture to be non-empty, tor-confirm to have passed, and a floor of genuine Tor guard packets. The Gateway is pinned to a fixed EntryNodes set (StrictNodes); a reserved address excluded from that set makes every packet to it an unambiguous test emission.

Accounts, verdicts, evidence

Account and snapshots

The leak lane runs in a dedicated account (persist-leak-<guest>), never shared with the install lanes; isolation, not disposability, is the property. Each run restores both VMs to a committed clean-live snapshot first; the account is unprivileged and covered by a host nftables drop as a backstop.

Version attribution

Both VMs carry a pinned version marker. Before a run, both markers must equal the requested version, else the run is reported as setup (rc 2), not a leak.

Verdict and results

rc 0 pass; rc 2 inconclusive; any other non-zero is a fail. Each run writes result.json to a read-only nginx results plane (onion-fronted); the leak evidence is the probe-battery output and the host pcap, not a screenshot.

Scope

Tooling in dist-ai; runs on disposable systems and does not ship. Trust boundary: org-ai-assisted. Companion lane: Kicksecure test suite.
