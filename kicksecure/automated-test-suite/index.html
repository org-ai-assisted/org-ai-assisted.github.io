Install tests

What it tests

Two goal states, R3 and R4.

R3: encrypted install

Download and signature-verify the release ISO, drive the stock Calamares installer through an erase-disk install with LUKS full-disk encryption, and confirm the LUKS volume unlocks at the next boot.

R4: installed boot

Detach the ISO, boot the installed disk, and confirm it reaches the first-boot desktop. With --checks, the release-check battery then runs inside the installed system.

How the install is driven

The live installer exposes no GUI automation interface. The host drives it by screen OCR, synthetic keyboard and mouse input, and VirtualBox guestcontrol.

OCR location

Screenshots are read with tesseract; each installer page is matched by its content text rather than fixed pixel coordinates, so the drive is independent of display resolution and firmware mode.

Launch

The GRUB unrestricted-install entry is selected by OCR (the default session refuses to install). install-host is started through VirtualBox guestcontrol, which returns an exit status, rather than a blind-typed terminal line.

Configuration pages

Welcome, Location, Keyboard, Partitions (erase disk, which enables encryption), the LUKS passphrase entered twice over stdin rather than argv, then Summary. Install is triggered with the Alt+I accelerator; the button caption OCRs unreliably.

Unlock and boot

The passphrase is entered at the boot-time LUKS prompt. The suite then waits for the installed system to reach first boot.

The check battery

One table (release-checks.bsh), shared with the upgrade-regression gate, run inside the installed system in a fixed order when enabled (--checks). The graphical-login check adds a render-first visual OCR cross-check (the painted desktop and the functional probe must agree); the rest are functional probes.

  • Install completion: installer reaches its done state.
  • User session: default, non-maintenance boot role.
  • Command-line login: shell session.
  • Graphical login: compositor running.
  • Networking: package mirror reachable.
  • systemcheck: systemcheck --cli --leak-tests --ci, retried.
  • Maintenance session: reboot into the maintenance boot role.
  • Upgrade: unprivileged full upgrade to completion.

Firmware and Secure Boot

Modes

Legacy BIOS, UEFI, and UEFI with Secure Boot. A reinstall-over-encryption chain covers installing onto a disk that already holds an encrypted system.

Module signing

Optional: run the installer MOK enrollment, read the per-machine certificate off the encrypted disk read-only from the host, enroll it (VBoxManage modifynvram), and reboot so a signed out-of-tree module loads under Secure Boot.

Accounts, verdicts, evidence

Accounts

VirtualBox state is per home directory, so the Linux account is the isolation boundary. A pre-bless version runs in a disposable per-version account (eph-run-<guest>-<version>); the blessed stable version runs in persist-stable-<guest>. Accounts are forced unprivileged with no passwordless sudo, checked fail-closed.

Verdict

rc 0 pass; rc 2 inconclusive (provisioning or infrastructure gap, not a product defect); any other non-zero is a fail.

Results plane

Each run writes result.json to a per-run directory under a read-only nginx results plane (onion-fronted) and repoints <name>/latest; a run that reaches first boot also captures a screenshot (best-effort -- an earlier failure has none).

Scope

Tooling in dist-ai; runs on disposable systems and does not ship. Trust boundary: org-ai-assisted. Companion lane: Whonix test suite.
